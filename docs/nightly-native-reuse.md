# Nightly native build reuse

Nightlies search earlier default-branch runs of `nightly-release.yml` for a compatible Chromium tree. Missing trees, failed lookups or transfers, failed extractions and invalid restored state fall back to clean preparation. Failed restoration or validation removes only the work directory created for that attempt; unexpected pre-existing trees are preserved and rejected. Failed and cancelled runs can supply checkpoints; pull requests, forks and other branches cannot.

Only `gh` subprocesses inherit the GitHub token. Source preparation, native build, Git fingerprinting and archive subprocesses receive an environment without GitHub tokens.

Discovery requests GitHub's documented maximum of 100 artifacts per page. One candidate iterator retains fetched pages and run metadata across attempts, so a failed artifact does not restart pagination or repeat trust lookups. API calls, candidate retries, downloads, extraction and configuration share an owner-selected total budget of one hour, configured as `FLECHA_REUSE_BUDGET_MINUTES: '60'`. The existing five-hour stage deadline can shorten that budget. The owner selected one hour to preserve time for a clean preparation and checkpoint handoff within GitHub's six-hour job limit. A failed artifact is excluded from subsequent selection; discovery tries remaining compatible native snapshots and indexed checkpoints before preparing cleanly. Expired allowance stops discovery, and API timeouts fall back without being mistaken for user cancellation.

Reuse subprocesses run asynchronously with pipes and isolated Unix process groups. At the deadline or cancellation, the runner force-stops the group, using noninteractive sudo for privileged Linux descendants, or uses Windows `taskkill /T /F`. It waits for inherited pipes to close before returning. There is no added termination grace period. If termination fails, preparation stops and preserves the owned tree and download directory instead of starting a competing fallback.

The SHA-256 compatibility key includes tracked Chromium revision, patches, branding, build configuration and Windows SDK setup; effective GN arguments with a normalized run number; depot_tools revision; source preparation code; platform and absolute workspace path; hosted runner image OS and version; and the selected Xcode or Visual Studio version. Changing a native input or runner image starts a clean build. Shell and packaging changes can reuse compiler outputs.

If hosted image metadata is unavailable, the key includes the current run ID to prevent cross-run reuse.

After restoration, the script checks the previous source SHA, compatibility key, Chromium revision, platform and depot_tools revision. It replaces the staged shell, regenerates GN arguments with the current version and run number, and clears package completion. Restored-tree configuration and GN generation stay inside the guarded reuse attempt and its deadline. Configuration failure discards that owned tree and tries another candidate or prepares cleanly. Ninja then checks the retained native outputs before current-source packaging runs. Package provenance records the current commit and the reused run, artifact and source commit.

Incomplete stages upload their usual checkpoint, then a small `reuse-<platform>-<key>-<stage>` index. Discovery ignores indexes whose checkpoints have expired or been superseded. A completed native build records `nativeComplete` before packaging. After the required package and checkpoint uploads, an optional step saves and uploads `native-<platform>-<key>`. This step also runs after packaging failure, when the compiled tree remains available. Later stages still use state-only completion markers.

Native snapshot creation, native artifact upload and reuse-index upload are optional. Their failure does not block packaging or the required package/checkpoint uploads. Snapshot compression uses only the time remaining in the existing five-hour stage allowance, then interrupts and removes a partial archive. The native upload step is limited to the whole minutes remaining in that same allowance. When no whole minute remains, it skips the upload and removes the archive. The last incomplete checkpoint is retained after completion, so skipping a full snapshot still permits partial reuse. Cancellation propagates.

Artifacts use the existing 35-day workflow retention policy. Older runs without compatibility indexes cannot seed reuse. The first compatible run must build the tree, and native changes still require compilation. Reuse adds full-tree compression and transfer after native compilation; it does not eliminate checkpoint overhead. The focused tests cover compatibility, trusted-run selection, archive restoration, shell replacement and provenance renewal. Full Chromium reuse and its speedup require a hosted nightly measurement.
